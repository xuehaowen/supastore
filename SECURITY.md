# Security reporting

This repository contains design documents only; there is no supported production release or active security-support window yet.

Do not post secrets, private customer data or exploitable deployment details in public issues. A private reporting channel has not yet been configured. Enabling GitHub private vulnerability reporting (or publishing a monitored security address), naming a responsible maintainer and defining a response process are mandatory before the first public application release. No monitored private channel or response-time commitment is claimed today.

Release security checks must cover admin/customer authorization, guest-token handling, privileged database functions, payment evidence storage, dependency updates and backup access. Publish supported versions and remediation guidance with each release.
